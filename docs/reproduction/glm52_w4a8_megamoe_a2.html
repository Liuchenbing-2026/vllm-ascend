Verified historical failure and fix

Verified fact: in the failed post-adaptation run, the third MegaMoe invocation left rank 3 waiting in token-per-expert all-gather while peer ranks did not enter the same communication phase. The run ended in CANN error 507014 after the AICore timeout. This was not an ABI or missing-library failure.

Historical root cause: the legacy mode 2 path did not apply the shared-expert multistream mutual-exclusion guard. The 0.27 migration uses the upstream unified enable_fused_mc2=1 setting, whose configuration layer disables that overlap before A2 MegaMoe is selected.

Start the service

Install vLLM v0.27.1 and this branch of vLLM Ascend in a compatible CANN runtime, map NPU devices 0–7 plus the standard Ascend management devices, and run:

MODEL_PATH=/data01/models/GLM-5.2-w4a8c8 \
DRAFT_MODEL_PATH=/data01/models/GLM-5.2-DSpark-NPU-0805 \
PORT=8077 \
bash examples/online_serving/serve_glm52_w4a8_megamoe_a2.sh

The launch script uses the 0.27 additional-config API with enable_fused_mc2=1, sets the A2 crossover at 512 tokens, and keeps shared-expert multistream overlap disabled. It uses TP=8, EP=8, DP=1, 4096 maximum batched tokens, the v1 model runner, full-decode graph mode, and DSpark with seven speculative tokens.
