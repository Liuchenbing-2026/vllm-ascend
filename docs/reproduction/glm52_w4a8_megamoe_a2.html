Verified failure and fix

Verified fact: in the failed post-adaptation run, the third MegaMoe invocation left rank 3 waiting in token-per-expert all-gather while peer ranks did not enter the same communication phase. The run ended in CANN error 507014 after the AICore timeout. This was not an ABI or missing-library failure.

Root cause: mode 1 already disabled multistream_overlap_shared_expert, but the newly introduced MegaMoe mode 2 did not apply the same mutual-exclusion guard. Commit dde3e817... extends that guard to modes 1 and 2 and adds a unit regression test.

Start the service

Use a CANN 9.1 runtime containing the exact vLLM and vLLM Ascend commits above, map NPU devices 0–7 plus the standard Ascend management devices, and run:

MODEL_PATH=/data01/models/GLM-5.2-w4a8c8 \
DRAFT_MODEL_PATH=/data01/models/GLM-5.2-DSpark-NPU-0805 \
PORT=8077 \
bash examples/online_serving/serve_glm52_w4a8_megamoe_a2.sh

The launch script explicitly sets VLLM_ASCEND_ENABLE_FUSED_MC2=2 and keeps shared-expert multistream overlap disabled. The validated service uses TP=8, EP=8, 4096 maximum batched tokens, and DSpark with seven speculative tokens.
