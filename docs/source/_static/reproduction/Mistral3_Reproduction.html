Mistral3 on vLLM Ascend

Pinned reproduction record for Shieldstral 1.0 3B, Mistral Small 4 119B/A6B FP8, and the Small 4 EAGLE draft checkpoint.

Recorded on 2026-08-17 (Asia/Shanghai). All revisions and image references below are immutable.

1. Scope and verified status

Shieldstral 1.0 3B

Verified: the pinned image plus the processor compatibility change reached a healthy OpenAI-compatible service and returned text and image responses.

Mistral Small 4 FP8

Partially verified: per-tensor FP8 unit coverage passed and the original weight_block_size=None loading failure was removed.

Small 4 EAGLE

Weights verified only: the official two-layer EAGLE draft checkpoint was downloaded and checksum-verified. A serving acceptance run was not completed.

Known Small 4 blocker: the last service attempt exited after FP8 setup with ValueError: No model architectures are specified because the checkpoint's nested text_config has model_type=mistral4 but no architectures field. This branch does not contain a separate Mistral4 inner-architecture fix. The Small 4 scripts below reproduce the current state; they are not a claim of a ready service.
No Shieldstral MTP: the Shieldstral 3B configuration and checkpoint contain no MTP, EAGLE, next-N, Medusa, or draft-model fields/weights. Do not launch it with method=mtp. The available speculative checkpoint belongs to Mistral Small 4 and uses EAGLE, not native MTP.

The final branch was not served again after its upstream rebase, following the request to publish without further service validation. The exact pre-rebase runtime behavior is recorded above.

6. Prepare the pinned Python overlay

Save this as /data02/reproduce-mistral3/prepare_overlay.sh. It does not start a service or access an NPU.

#!/usr/bin/env bash
set -euo pipefail

IMAGE=quay.io/ascend/vllm-ascend@sha256:464297cc5046dde0e60350b5f5e505c58141b87d4ff7a8691abd06cf0632c50f
IMAGE_ID=sha256:f5be9d53778ad97a1d6ffce3ba04ee96162a485f0855d4741d8ef9d37761123e
REPO=/data02/reproduce-mistral3/vllm-ascend
PIN=f64c16d9924e6d2b8ce55adca97b1b5345716df0
OVERLAY=/data02/reproduce-mistral3/runtime-overlay

test "$(docker image inspect --format '{{.Id}}' "${IMAGE}")" = "${IMAGE_ID}"
git -C "${REPO}" merge-base --is-ancestor "${PIN}" HEAD
git -C "${REPO}" diff --exit-code "${PIN}"..HEAD -- vllm_ascend

install -d -m 755 \
  "${OVERLAY}/vllm_ascend/patch/platform" \
  "${OVERLAY}/vllm_ascend/quantization/methods"

# Preserve the initializer bundled in the image and add only this patch import.
docker run --rm --entrypoint cat "${IMAGE}" \
  /vllm-workspace/vllm-ascend/vllm_ascend/patch/platform/__init__.py \
  >"${OVERLAY}/vllm_ascend/patch/platform/__init__.py"
if ! grep -Fq 'import vllm_ascend.patch.platform.patch_mistral3_processor' \
  "${OVERLAY}/vllm_ascend/patch/platform/__init__.py"; then
  printf '\nimport vllm_ascend.patch.platform.patch_mistral3_processor  # noqa: F401\n' \
    >>"${OVERLAY}/vllm_ascend/patch/platform/__init__.py"
fi

runtime_files=(
  vllm_ascend/patch/platform/patch_mistral3_processor.py
  vllm_ascend/quantization/fp8_config.py
  vllm_ascend/quantization/method_adapters.py
  vllm_ascend/quantization/methods/__init__.py
  vllm_ascend/quantization/methods/fp8_per_tensor.py
  vllm_ascend/quantization/methods/w8a8_dynamic.py
)
for path in "${runtime_files[@]}"; do
  install -D -m 644 "${REPO}/${path}" "${OVERLAY}/${path}"
done

# Compatibility glue only for the pinned af337dfa image: official main later
# moved _MEGA_MOE_SUPPORTED from ascend_forward_context to ascend_config.
W8A8=${OVERLAY}/vllm_ascend/quantization/methods/w8a8_dynamic.py
grep -Fq \
  'from vllm_ascend.ascend_config import _MEGA_MOE_SUPPORTED, get_ascend_config' \
  "${W8A8}"
sed -i \
  -e 's/from vllm_ascend.ascend_config import _MEGA_MOE_SUPPORTED, get_ascend_config/from vllm_ascend.ascend_config import get_ascend_config/' \
  -e 's/from vllm_ascend.ascend_forward_context import _EXTRA_CTX, MoECommType/from vllm_ascend.ascend_forward_context import _EXTRA_CTX, _MEGA_MOE_SUPPORTED, MoECommType/' \
  "${W8A8}"

find "${OVERLAY}" -type f -print0 | sort -z | xargs -0 sha256sum \
  >"${OVERLAY}/SHA256SUMS"
echo "Overlay ready: ${OVERLAY}"

#!/usr/bin/env bash
set -euo pipefail

IMAGE=quay.io/ascend/vllm-ascend@sha256:464297cc5046dde0e60350b5f5e505c58141b87d4ff7a8691abd06cf0632c50f

NAME=repro-shieldstral-1-0-3b
PORT=8914
HOST_NPU=4

test -f "${MODEL}/model.safetensors"

  echo "Container already exists: ${NAME}" >&2
  exit 2
fi
if ss -ltn | grep -Eq ":${PORT}[[:space:]]"; then
  echo "Port is occupied: ${PORT}" >&2
  exit 3

  echo "NPU ${HOST_NPU} is occupied or its state is ambiguous" >&2
  exit 4

  --name "${NAME}" \
  --network host \
  --ipc host \
  --device "/dev/davinci${HOST_NPU}:/dev/davinci0" \

10. Shutdown and release checks

#!/usr/bin/env bash
set -euo pipefail

NAME=${1:?usage: stop_service.sh CONTAINER_NAME PORT}
PORT=${2:?usage: stop_service.sh CONTAINER_NAME PORT}

docker stop --time 60 "${NAME}"
test "$(docker inspect --format '{{.State.Status}}' "${NAME}")" = exited
if ss -ltn | grep -Eq ":${PORT}[[:space:]]"; then
  echo "Port ${PORT} is still listening" >&2
  exit 2
fi

# Review both the executable-aware worker list and every NPU process table.
ps -eo pid=,comm=,args= | awk \
  '$2 ~ /^(python|python3|vllm)$/ && $0 ~ /(vllm serve|EngineCore|VLLM::)/' || true
npu-smi info

Do not remove containers or terminate processes until their ownership and exact target have been confirmed.

11. Reproduction interpretation

  • A healthy Shieldstral result is HTTP 200 from /v1/models and a non-empty chat completion for both text and image requests.
  • The current Small 4 result is successful traversal of the per-tensor FP8 configuration path followed by the independently recorded nested-architecture error.
  • Do not report EAGLE acceptance or MTP performance until the base Small 4 service reaches ready state and a controlled base-versus-EAGLE correctness run has completed.
  • Do not describe Shieldstral 3B as MTP-capable unless a separate compatible draft checkpoint is explicitly supplied and validated.
