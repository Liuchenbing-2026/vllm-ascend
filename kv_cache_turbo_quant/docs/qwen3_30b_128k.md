# Qwen3-30B-A3B(纯 GQA, head_dim=128)128k 实测

> 日期:2026-10-10。环境:Atlas 800T A2,vllm-ascend 0.28.0rc,TP=2,enforce-eager,
> max_model_len=133120(YaRN x4 via `--hf-overrides`,原生 40960)。
> base 输出 1k 全量;tq 侧 c1/c2 输出 128、c4+ 输出 32(TPOT 稳态均值口径可比;
> c4+ TTFT 受 base 侧长 decode 占卡影响,非完全同口径)。

## 容量(核心收益)

| 指标 | baseline | store(4-bit) | 倍数 |
|---|---|---|---|
| GPU KV cache size | 351,616 tokens | 1,364,096 tokens | **3.88x** |
| 133,120 上下文最大并发 | 2.64x | 10.25x | **3.88x** |

即 baseline 同显存只能同时服务 2 条 128k 请求,开算子后可服务 10 条。

## TTFT / TPOT A/B

| 并发 | TTFT base | TTFT tq | TPOT base | TPOT tq | TPOT 倍数 |
|---|---|---|---|---|---|
| 1 | 37.9 s | 38.7 s (+2.1%) | 193.8 ms | 3127.1 ms | 16.1x |
| 2 | 56.2 s | 60.4 s (+7.5%) | 221.2 | 6351.3 | 28.7x |
| 4 | 197.3 s | 107.4 s | 229.9 | 12927.1 | 56.2x |
| 8 | 474.7 s | 211.8 s | 229.4 | 27135.4 | 118x |
| 16 | 1016.4 s | 709.8 s | 230.6 | 31157.8 | 135x |
| 32 | 2129.9 s | 1652.7 s | 232.8 | 33895.6 | 146x |

## 结论

- 写路径开销小(c1/c2 TTFT +2~7%),与 Qwen3.8-27B 结论一致。
- 容量 3.88x 是纯 GQA 的标准收益(hybrid 因仅 1/4 层可压缩为 2.50x)。
- store v1 读路径 TPOT 劣化 16~146x,比 3.8(9~26x)更严重:30B 为 48 层全注意力,
  每层每请求都要 Python 解压,开销随层数 × 并发线性放大。**v1 仅为容量/正确性验证中间态,
  时延正收益需融合读路径(per-row affine int4 + 原生 FIA antiquant,或自研融合 kernel)。**

## 复现

```bash
# 服务(容器内),30B 原生 40960,128k 需 YaRN
VLLM_ASCEND_KVTQ_STORE=1 VLLM_ASCEND_KVTQ_BITS=4 \
ASCEND_RT_VISIBLE_DEVICES=6,7 \
python3 -m vllm.entrypoints.openai.api_server \
  --model /home/models/Qwen3-30B-A3B --served-model-name qwen3-30b \
  --tensor-parallel-size 2 --max-model-len 133120 --max-num-batched-tokens 133120 \
  --hf-overrides '{"rope_scaling":{"rope_type":"yarn","factor":4.0,"original_max_position_embeddings":40960}}' \
  --gpu-memory-utilization 0.92 --no-enable-prefix-caching --enforce-eager --port 8379
# 启动日志应出现: GPU KV cache size: 1,364,096 tokens ... 10.25x
# baseline 去掉两个 VLLM_ASCEND_KVTQ_* 环境变量(KV size 351,616 / 2.64x)
```
